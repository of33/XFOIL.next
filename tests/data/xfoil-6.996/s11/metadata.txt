XFOIL 6.996 S11 polar text I/O fixtures
=======================================

Version:            XFOIL 6.996 polar text I/O (S11)
Purpose:            canonical base/side/element round-trip, exact-token
                    rejection, append-schema preflight and explicit
                    6.996 broken-side-order migration.
Oracle policy:      no repository Fortran source, golden, reference or
                    old 6.99 fixture changed.
Source baseline:    fortran-src/xfoil-6.99 and
                    fortran-src/xfoil-6.996.

Canonical contract:
  - base columns: alpha, CL, CD, CDp, CM;
  - side columns: Top_/Bot_ pairs per JPOL, side-major data in the same
    order;
  - element columns after sides: N outer, K inner;
  - element names Cx_n, Cy_n, Cm_n, CDv_n;
  - element-free files retain the 6.99/current base bytes;
  - canonical LF line endings.

Reader compatibility:
  - 6.996 Version 7.00 side-transposed files are rejected in canonical
    mode;
  - PolarReadCompatibility::xfoil6996BrokenSideOrder applies exactly one
    documented side transpose and is never selected automatically.

Generation:
  canonical-base.pol:
    controlled 6.99 format-probe output from the external audit area,
    produced from the same fixed values used by the S11 matrix probe.
  broken-6996-base-v700.pol:
    controlled unpatched 6.996 POLWRIT base output from the external
    audit area; only the header Version field was changed from 0.00 to
    7.00. The side-major data defect itself is unchanged.
  canonical-elem1/elem4/multiel.pol:
    deterministic output of writePolarTextChecked on the controlled
    S11 request, then stored as read-only round-trip fixtures. The
    tests re-read them, rebuild the request from the parsed metadata and
    require byte-identical output.
  malformed fixtures:
    derived from canonical-base.pol by one documented local change;
    no oracle byte target is claimed for them.

Case IDs:
  canonical-base.pol: base regression against the existing 6.99 byte
                      contract.
  canonical-elem1/elem4/multiel.pol: exact header/data layout and
                      byte-identical parsed -> write round trip.
  broken-6996-base-v700.pol: canonical rejection and opt-in migration.
  unknown/duplicate/truncated: exact-token and row-width rejection.
  incompatible-append.pol: PolarAppendCheck refusal without filesystem
                      mutation.
